Way 1 · The best one

Connect Krate to your AI.

If you use Claude Desktop or Cursor, you can describe an app in the chat you already have open and get a working file back. It writes the code, builds it, checks it, and hands you the finished .krate. You never type a command.

One command sets it up.

1

Run one command.

It finds Claude Desktop or Cursor on your computer, shows you the one line it wants to change, and asks before changing anything. Nothing else in the file is touched, and a copy of the old one is kept.

krate connect

Not sure what you have installed? krate ai prints the AI tools Krate can find on your machine.

2

Restart, and check it worked.

Quit Claude Desktop properly and open it again, or reload Cursor. Closing the window is not enough. Then ask your AI:

What Krate tools do you have?

These seven are the ones that build apps:

  • krate_schema
  • krate_examples
  • krate_start_build
  • krate_build_status
  • krate_check
  • krate_package
  • krate_run

You will also see inspect_bundle and run_component, which are for opening a .krate somebody sent you rather than making one. Nine in total means it is wired up correctly.

3

Then just talk.

That is the whole setup. From here you describe apps in ordinary sentences:

Build me a habit tracker that shows a weekly grid and remembers my streaks. Package it as a .krate.

What happens next, so nothing is a surprise:

  1. The model reads Krate's API reference first, so it writes against the real thing instead of guessing.
  2. It starts a build and gets a job id back straight away. A build takes two to five minutes. The model polls it and can tell you what stage it is at.
  3. It checks the result with the same six-stage oracle the command line uses: the app has to build, import nothing outside krate:*, run, and paint a frame.
  4. You get a .krate file. Send it to anyone and they double-click it.

Way 2 · Nothing to install

Paste one prompt into any chat.

If you would rather not connect anything, there is one prompt that teaches a model how Krate apps are written. Paste it at the top of a chat and then describe your app in the same conversation. The model writes correct Krate code, and you build it locally.

This works anywhere you can paste text: ChatGPT, Claude, Cursor, Copilot Chat, anything. Nothing is installed and nothing is configured.

The prompt is long on purpose -- it carries the whole API -- so it lives on its own page with a copy button.

Way 3 · The terminal

One command.

If you are already in a terminal, this hands your request to an AI tool you have installed and writes the finished file:

krate create "a habit tracker that saves my streaks" --output habit-tracker.krate --agent claude

--output is required: it is the file you get back. --agent picks which installed AI writes it.

Rather than assemble that by hand, there is a builder that writes the command for you with the quoting already handled, plus the full walkthrough of what to expect and how to share the result.

Which AI

Use the AI you already have.

Krate does not run an AI for you. It drives a tool that is already on your machine and already signed in to you, which is why it never sees your account and why the build happens on your computer. Run krate ai to see what you can use right now -- it prints the tools it found, the ones you could add, and the exact command to make your first app.

Claude Code
npm install -g @anthropic-ai/claude-code
--agent claude
OpenAI Codex
npm install -g @openai/codex
--agent codex
Google Gemini
npm install -g @google/gemini-cli
--agent gemini
GitHub Copilot
npm install -g @github/copilot
--agent copilot
xAI Grok
Install the Grok CLI from xAI. It installs as agent.
--agent grok

Using something else? Any tool that can write files from a prompt works. Pass it with --author-cmd "your command" instead of --agent. Krate hands it the request and a working starter, then checks whatever it writes.

No AI at all? You can still make an app. Leave the AI out and Krate starts you from a built-in template.

When the answer is no

You find out in a second, not in five minutes.

Some things a Krate app cannot do. It runs in a sandbox, so it cannot reach into the other programs on your computer, sign in to your accounts, or run in the background while it is closed.

If you ask for one of those, you are told immediately -- with the reason, and with the nearest thing that would actually work:

Krate cannot build that: a Krate app runs in a sandbox and cannot read the apps or libraries already on your computer, so it cannot get at your real mail, photos, contacts, or messages.

Try instead: an app that works on files you pick yourself, or on data you type in.

Stopped before writing any code, so nothing was spent on an app that could not have worked.

This is deliberate. Krate would rather say no in a second than spend five minutes producing an app that looks convincing and does not do what you asked. It only refuses what is certainly impossible -- anything it is unsure about, it builds.

What you get

One file, and two ways to hand it over.

Whichever way you built it, the result is a single .krate file that runs on Mac, Windows, and Linux.

Send the file

Attach the .krate to an email or a chat, the way you would send a photo. Whoever gets it double-clicks it, or runs krate run on it. This works today, with no account.

Publish for a link

Upload it and get back a URL that anyone can run straight from the link.

krate publish ./habit-tracker.krate

It prints a line like krate run <url> that anyone can paste.

Troubleshooting

If something goes wrong.

My AI does not see any Krate tools

Restart the app fully -- an MCP server is only picked up at start. If it still finds nothing, the usual cause is that krate is not on the PATH the app sees. Run which krate on macOS or Linux, or where krate on Windows, and put that full path in "command" instead of the bare word. Check the JSON is valid too: a trailing comma is enough to make the whole file be ignored.

The build seems to hang

A build takes two to five minutes, and that is normal. The model gets a job id back immediately and can poll it with krate_build_status, so ask it what stage the build is at rather than waiting in silence.

It failed installing the build tools

Update to the latest version of Krate and try again. The install step has improved across releases, and a newer Krate handles setups an older one tripped on. Reinstall from the home page, then run krate doctor to confirm your setup is complete.

I would rather not connect anything

Use Krate Mode: one prompt pasted into any chat, nothing installed. Or use the terminal command.
