The .krate format: one app file for every screen

A .krate is one small app file for every screen: the same bytes run natively on macOS, Windows and Linux, and sent as a link, it opens in any modern browser, phones included, with nothing to install and no account. The app starts with no access to your files or the network and asks before it touches either.

One file, every screen

You build the app once and get one .krate file. Send it as a link and it opens in any modern browser, phones included, with nothing to install and no account. On Mac, Windows and Linux, the Krate runtime runs the same file natively, as a real window with no browser or WebView inside. The runtime is installed once and every Krate app after that is just a file.

There is no build per operating system, no build per processor and no package per platform to sign. Krate does the per-platform work in its runtimes, once, for every app. See how that compares with Electron and Tauri.

What is inside a .krate file?

The bundle is a ZIP-based application format. Its core entries are manifest.toml and code.wasm, and it can also carry assets, source and SDK material. Apps made in Studio carry their editable source, so you can keep changing them.

The manifest names the app and the access it asks for. The component calls Krate interfaces described in WIT, and the runtime supplies them. Files, the network and other host resources go through the capability model, so the app reaches only what the person allowed.

Read the bundle implementation and interface definitions. Both are open source.

Small by design

Krate's Notes app is one 36.6 KiB file. Holding 50,000 lines, it used 178.5 MiB of memory against 2,299.4 MiB for MarkText, an Electron editor: 13x less. A warm open took 237.1 ms against 611.5 ms: 2.6x faster. MarkText takes 284.6 MiB installed; the Krate runtime is installed once and shared by every app.

Measured on 25 August 2026 on an Apple M4: Krate's Notes app against MarkText 0.17.1 on the same 50,000-line notes workload, an equivalent workload. Read the method.

Verify a shared file yourself

Copy the same file to each machine, record krate --version, see what it asks for and run it:

krate --version
krate run app.krate --dump-caps
krate run app.krate --prompt

Compare the full-file SHA-256 on each host: shasum -a 256 app.krate on macOS, sha256sum app.krate on Linux, Get-FileHash app.krate -Algorithm SHA256 in Windows PowerShell. Then use the app the same way on each: load data, save, close and reopen.

Bring your project over

Krate is for real software, from small tools to editors, dashboards and games. Run krate port (beta) on an existing project to see how it maps to Krate's interfaces, or open it in Krate Studio and let the AI bring it over. Electron apps go from hundreds of megabytes to one small file. The porting guide walks through it, and the capability reference lists what apps can use today.

Questions

What does the person opening a .krate need?

Nothing, to open a link: the app runs in any modern browser, phones included, with no account. To run it natively, the Krate runtime, installed once. They never need Rust, your source or your build tools.

Can a .krate file run on a phone?

Yes. Send it as a link and it opens in the phone's browser, with nothing to install and no account.

Is a .krate the same as a Rust crate?

No. A crate is a Rust package on crates.io. A .krate file is a packaged application: a WebAssembly component, its manifest, and optional source and assets.

How do I check that two copies are the same file?

Compare SHA-256 hashes: shasum -a 256 on macOS, sha256sum on Linux, Get-FileHash in Windows PowerShell. Matching hashes mean identical bytes.
