What is in this checkout.

Krate lets developers package software as one .krate file that runs through native Krate runtimes on macOS, Windows and Linux.

The recipient installs a compatible Krate runtime once. Applications use supported Krate APIs; existing desktop binaries do not become portable without adaptation.

Latest published release at generation: v0.5.0.

A .krate bundle contains a WebAssembly component and manifest, and can also carry source, SDK interfaces and assets. Full bundle bytes, uncompressed code payload, runtime download and installed runtime size are different measurements. Code payload means the uncompressed code.wasm entry; older bundles without source are identified instead of presented as the size of all current apps. The shared runtime is not included.

Test configuration is not a test result

The repository's ported-app replay script names 10 checks: bounce, chart, cubes, ddh, envelope, eo2, grex, hexyl, mdview, savings. This list says what the script is configured to exercise, not whether the latest run passed.

Inspect the replay script, CI run results and release notes for the revision and host you intend to use. A file existing in this checkout does not prove it works with every published runtime version.

Choose a supported application

Start with the porting guide and current limits. Runtime APIs and bundle formats evolve; use a compatible runtime, SDK and artifact.

  • Interface coverage
  • Widget coverage
  • Developer quickstart
  • AI-assisted authoring in Studio

Applications begin without file or network access and receive approved capabilities through the runtime. This boundary is not a guarantee of bug-free or harmless software; review the threat model and only run apps you trust.

Performance needs its own evidence

The measurement report describes one architecture-matched notes workload and separates full bundle, code payload and shared-runtime costs. This inventory makes no speed, memory or size-ratio claim against unrelated applications.
