QUESTIONS

Direct answers about Krate.

These came from people seeing a 37 KB desktop app open on three operating systems for the first time. The short answer comes first.

01How can the same .krate file open on Mac, Windows, and Linux?

The app does not call AppKit, Win32, or Linux APIs directly. It calls Krate interfaces described with WIT. The Krate host on each operating system translates approved calls into local behavior.

The .krate file carries the WebAssembly component and its requested access. It is one portable app artifact, not three native installers hidden in one download.

02Why not use an HTML file, browser link, or Electron?

A browser link is the right answer when an app fits inside the browser. Krate is for local software that needs files, desktop behavior, or other host features that a web page cannot use cleanly.

An Electron app ships a browser engine and still needs platform packaging. A Krate app is a WebAssembly component. It does not bundle a browser per app, and the shared runtime controls its access to the computer.

03So is Krate basically Docker?

No. Docker packages server environments and operating-system dependencies into containers. Krate packages a desktop app as one portable WebAssembly component and gives it native windows through a shared host.

A .krate file is made to be sent to a person, opened like a document, and stopped from reaching anything the person did not approve.

04Why can Krate apps be so small?

Every app uses the same Krate runtime instead of carrying another browser engine, renderer, and operating-system wrapper. The app file contains the app, its source, and the access it requests.

In published proof, a playable Breakout game is 13 KB and the notes app used in our benchmark is 37 KB. Bigger apps and large media assets will still be bigger. Krate removes duplicated machinery; it does not make data disappear.

05Does "no installer" mean I never install Krate?

You install Krate once. After that, every .krate app opens like a file. There is no separate installer, dependency setup, or operating-system build for each app.

That shared runtime is what keeps app files tiny, makes the same bytes portable, and enforces the permission screen.

06Can an app hide what it accesses or ignore the permission screen?

The permission list is not only a label written by the app. Krate checks supported host operations at the runtime boundary. If the app tries an operation that was not granted, the call is denied before the host adapter performs it.

If a required permission is denied, the current app flow refuses to start and explains what is missing.

07Does Krate really use less memory?

On the same 50,000-line notes workload, MarkText 0.17.1 used 2.3 GB across five processes. The Krate notes app used 95 MB in one process. It also opened in about 0.2 seconds instead of 1.8 seconds.

That is a measured comparison on an M4 Mac, not a promise for every possible app. The method and raw results are public.

08Is Krate ready for any untrusted app from the internet?

Not yet. The capability boundary works, but v0.1.50 is still beta software and Krate is not yet claiming adversarial hardening against every hostile third-party app.

Use the published examples or apps you are testing yourself. The current limits and threat model are public.

09Does the name collide with a Rust "crate"?

Rust calls a package a crate, so the similarity is real. Krate uses a different spelling and refers to the portable container that carries an application and its requested access.

We will keep making the distinction explicit wherever Rust developers could reasonably confuse the two.
