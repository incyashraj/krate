Questions

Questions

Short answer first, the boundary underneath.

01What do I write, and in what?

Rust today, compiled to a WebAssembly component. Apps use krate:* interfaces for system access rather than wasi:* imports. You can write the code yourself or use AI in Krate Studio.

krate check-app checks compilation, imports and a headless run. It helps catch integration errors; you still test the app's behaviour. Start with the developer quickstart.

02Can I bring an app I already have?

krate port reads your project and reports what maps cleanly, what needs a capability, and what will not work. It is read-only: it never builds, runs or edits your source.

Reusable application logic is a good starting point. UI code and direct operating-system calls need Krate interfaces, and dependencies must support the WebAssembly target. The porting guide walks through the process.

03What can I build, and what are the current limits?

Krate exposes interfaces for desktop UI, drawing, storage, networking and other system resources. The capability and limits reference records what is implemented and the boundaries to check for your app.

For examples you can inspect, see the app gallery and repository inventory.

04How can the same .krate file open on Mac, Windows, and Linux?

The app does not call AppKit, Win32, or Linux APIs directly. It calls Krate interfaces, and the Krate player on each operating system translates approved calls into local behavior.

The .krate file carries the WebAssembly component and its requested access. It is one portable app, and the same bytes run on all three desktops.

05Why not use an HTML file, browser link, or Electron?

A browser link works well for web applications. Krate gives developers a file they can distribute directly for local execution. Krate Cloud is optional; an app's own online features still need their services.

An Electron app bundles Chromium and Node.js and uses platform-specific packages. Krate apps share a native runtime rather than bundling a browser per app. See the desktop distribution comparison.

06Can an app hide what it accesses or ignore the permission screen?

Krate checks every operation at the boundary, so the list is not something the app writes about itself: if the app tries something that was not granted, the call is denied before it reaches the operating system.

If a required permission is denied, the app refuses to start and explains what is missing.

07Is Krate ready for any untrusted app from the internet?

Not yet. The capability boundary is working and useful, but Krate is young and we are not claiming production hardening against hostile third-party code today.

Open apps from people you know, or from the gallery. The current limits and threat model are public.

08Why does the person receiving an app need Krate?

Krate is the player, like a media player for application files. Its native runtime handles operating-system differences and enforces permissions, so developers can send the same app file to all three desktops.

Install the player once, then open .krate files through it. An app needs a runtime version that supports its interfaces. The opening guide gets you started.

09Does the name collide with a Rust “crate”?

Rust calls a package a crate, so the similarity is real. Krate uses a different spelling and refers to the portable container that carries an application and its requested access.

We keep the distinction explicit wherever Rust developers could reasonably confuse the two.

10What does “your first app is on us” mean?

In your browser, Krate's own AI makes one app for you and one change to it, and we pay for it. No API key, no card, nothing to install.

Only an app that is actually made counts. A build that fails, or that we could not finish, costs you nothing and you can try again.

11What happens after my free app?

The app is a file, and it stays yours: open it, publish it, send it to anyone.

To keep making, use Krate Studio on your own computer, which is free and unlimited with the AI you already use. Or add your own API key in Studio's settings in the browser and keep going there.

12Do I need an account?

Not to open apps. Not to make apps in Krate Studio on your own computer, either; there you only sign in to publish.

Making an app in the browser does need one, so your free app is counted once and your work is kept. Sign in with GitHub, Google or a link sent to your email.
