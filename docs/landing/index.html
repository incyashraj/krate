It's just an app

You get a real app. It opens a window, keeps your settings, saves your things in its own database, remembers your sign-in, and can send you a notification or open a link.

What it cannot do is help itself. Before it opens, Krate shows you what it wants, in plain words rather than permissions jargon, and it gets only what you allow. An app that keeps a list never sees your folders.

The same file works on Mac, Windows, and Linux. Not three downloads. One.

Where it runs

Six builds. Both chips. All three systems.

Every release publishes each of these, and the same app file opens on all of them.

Shipping now

  • macOS on Apple Silicon tested
  • macOS on Intel
  • Windows on Intel and AMD
  • Windows on ARM tested
  • Linux on Intel and AMD
  • Linux on ARM

Windows on ARM covers a Windows VM on an Apple Silicon Mac, which is how most people try Windows without owning a Windows machine. Linux on ARM covers a Raspberry Pi 4 or 5 and most cloud ARM instances. Marked tested where a person has installed and run it, rather than only built it.

Next

  • Speech on ARM builds. Everything else works there today; transcription needs a newer C++ toolchain than those build containers carry.
  • A signed installer for Windows and macOS, so neither system warns about an unknown developer.
  • Linux on RISC-V, once there is somebody asking for it.
  • Phones and tablets. The runtime is portable and the window layer is not. Real work, not a recompile.
  • The browser. Krate apps are already WebAssembly, so this is the shortest path of the four and the one that would let somebody try an app without installing anything at all.

Questions people asked

Direct answers about Krate.

These questions came from developers seeing Krate for the first time. The short answer is first, with the technical boundary underneath it.

04 / AIHow does Krate make an AI-created app safer?

AI-generated code receives no special trust. During authoring, Krate rejects an app if it imports system interfaces outside the Krate capability boundary. At runtime, the app begins without access to the user’s files or network.

The app requests specific capabilities, the user reviews them, and the runtime enforces the decision before approved host operations happen. This limits what the app can reach. It does not prove that the app is bug-free.

08 / TodayWhat can Krate apps do today, and can it convert my existing app?

Today Krate is best for small apps that fit its current UI and capability set, such as notes, lists, text entry, buttons, local persistence, and portable command-line tools.

It does not automatically convert an existing Swift, Electron, Tauri, or native application yet. Current apps must use Krate APIs. AI-assisted porting is a planned development target, and it will reimplement supported behavior rather than pretend an incompatible binary became portable.

09 / CloudDoes Krate Cloud run the app on someone else’s server?

That is not the plan. Krate Cloud is the planned publishing and distribution layer for discovery, publisher identity, signing, sharing, and updates.

The app still opens through the Krate runtime on the user’s own computer, where the user reviews and controls local access. Krate Cloud is planned and is not available today.

About

Who is building this.

Krate is built by Yashraj Pardeshi, its founder and builder. He has been building it solo since April 2026, in public, from Singapore.

The problem it answers has not been solved: software still cannot move between computers the way a file can, and you cannot tell what a program does before you run it. Krate is one answer to both: a single app file that opens on Mac, Windows, and Linux, and carries the list of what it is allowed to do on the outside, where you can read it before anything runs.

Every claim here is checkable. Machines he has never touched open the app, type into it, and photograph the result on every push; the evidence is in the build logs. It is early, and the limits are published alongside the product.
