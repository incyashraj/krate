Questions people asked

Direct answers about Krate.

These questions came from developers seeing Krate for the first time. The short answer is first, with the technical boundary underneath it.

01 / DockerIs Krate just Docker for desktop apps?

No. Docker packages a process with an operating environment. It is excellent for servers, development, and isolated workloads. Krate packages an application and the access it requests into one file a person can open locally.

A container mainly answers where code runs. Krate also answers what that specific app may access. Files, network addresses, windows, and other host features stay behind explicit capabilities.

02 / WebWhy not use an HTML file, browser link, or Electron?

A browser link is the right answer when an app fits inside the browser. Krate is for local software that needs files, desktop behavior, or other host features that a web page cannot use cleanly.

An Electron app ships a browser engine and still needs platform packaging. A Krate app is a WebAssembly component. It does not bundle a browser per app, and the shared runtime controls its access to the computer.

03 / PortableHow can the same .krate file open on Mac, Windows, and Linux?

The app does not call AppKit, Win32, or Linux APIs directly. It calls Krate interfaces described with WIT. The Krate host on each operating system translates approved calls into local behavior.

The .krate file carries the WebAssembly component and its requested access. It is one portable app artifact, not three native installers hidden in one download.

04 / AIHow does Krate make an AI-created app safer?

AI-generated code receives no special trust. During authoring, Krate rejects an app if it imports system interfaces outside the Krate capability boundary. At runtime, the app begins without access to the user’s files or network.

The app requests specific capabilities, the user reviews them, and the runtime enforces the decision before approved host operations happen. This limits what the app can reach. It does not prove that the app is bug-free.

05 / AccessCan an app hide what it accesses or ignore the permission screen?

The permission list is not only a label written by the app. Krate checks supported host operations at the runtime boundary. If the app tries an operation that was not granted, the call is denied before the host adapter performs it.

If a required permission is denied, the current app flow refuses to start and explains what is missing.

06 / SecurityIs Krate ready for any untrusted app from the internet?

Not yet. Krate is pre-alpha. The capability boundary is working and useful, but the project is not claiming production hardening against hostile third-party code today.

Use the published examples or apps you are testing yourself. The current limits and threat model are public.

07 / RuntimeWhy does the person receiving an app need the Krate runtime?

The runtime is the stable layer that makes one app file portable and enforces its access. Without it, every app would need to bring a separate engine and separate operating-system code.

You install Krate once. After that, each .krate file can use the same host, permission model, and opening flow.

08 / TodayWhat can Krate apps do today, and can it convert my existing app?

Today Krate is best for small apps that fit its current UI and capability set, such as notes, lists, text entry, buttons, local persistence, and portable command-line tools.

It does not automatically convert an existing Swift, Electron, Tauri, or native application yet. Current apps must use Krate APIs. AI-assisted porting is a planned development target, and it will reimplement supported behavior rather than pretend an incompatible binary became portable.

09 / CloudDoes Krate Cloud run the app on someone else’s server?

That is not the plan. Krate Cloud is the planned publishing and distribution layer for discovery, publisher identity, signing, sharing, and updates.

The app still opens through the Krate runtime on the user’s own computer, where the user reviews and controls local access. Krate Cloud is planned and is not available today.

10 / NameDoes the name collide with a Rust “crate”?

Rust calls a package a crate, so the similarity is real. Krate uses a different spelling and refers to the portable container that carries an application and its requested access.

We will keep making the distinction explicit wherever Rust developers could reasonably confuse the two.
