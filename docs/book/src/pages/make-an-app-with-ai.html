Set up once

Get the krate tool

You need this on any computer where you want to open or make Krate apps. It is one line. Paste it into a terminal and press enter. On a Mac, Terminal is in Applications › Utilities.

curl -fsSL https://raw.githubusercontent.com/incyashraj/krate/main/scripts/install.sh | sh
That downloads the ready-made tool and sets it up for you. When it finishes you have a tool called krate and setup is done. It carries everything it needs inside it, so you never repeat this step. Building from source? Install Rust, then cargo build --release -p krate-cli.
For anyone

Someone sent you a .krate

1

Double-click the file

Before anything runs, a window appears listing exactly what the app wants to use. For example a window, and read and write to its own folder. Nothing else on your machine is reachable.

2

Read the list, then allow it

You can see everything it is asking for. If it looks right, allow it and the app opens. If it ever asks for more than it should, that is your sign to say no.

3

Use it, close it, open it again

It works like any normal app, and everything you do is saved as you go. Open the file again later and it is exactly as you left it. The same file works on Mac, Windows, and Linux.

Try saying no. Open it again and decline what it needs. It does not start at all. It never opens half working. That check happens before the app's code runs, and that wall is the whole point.
For makers

Describe an app. Get one file to share.

1

Say what you want

Open a terminal and run this, changing the sentence to describe your app.

krate create "Make a checklist app that saves my items" \
  --output checklist.krate
2

Krate does the rest

It writes the app, builds it, checks it can only touch what it says, packages it, and proves it works before the file even exists.

Created checklist.krate
  requested access:
    - a window
    - read and write its own "checklist" folder

Send checklist.krate to someone; they double-click it to open.
3

Send the file

It is one ordinary file. Email it, message it, or drop it in a shared folder. Whoever gets it opens it with the steps in the first path above. They do not need to trust you or read any code.

Want to write the code yourself? You can. Write a Krate app and package it with krate pack. The full developer version is in the Create and Share an App guide.
For AI teams

Give your agent a safe way to hand people real apps

Your agent already writes code. The hard part is letting a person run that code without handing it their whole machine. Krate is that missing piece: your agent writes the app, and the result is one file that can only touch what the user allows, checked and proven before it reaches them.

1

Your agent writes the app

Point krate create at your agent with --author-cmd. Your agent is handed the request and writes the app. Nothing about your model or stack has to change.

krate create "Make a checklist app that saves locally" \
  --author-cmd "your agent command" \
  --output checklist.krate
2

Krate checks and proves it

Krate builds what your agent wrote, confirms it uses only Krate's safe interfaces and never the raw machine, packages it, and proves its permission wall. If the agent reached for something unsafe, it is caught here, not on a user's computer.

3

You get a file and a record

Out comes one .krate to hand to the user, plus a short transcript listing exactly what it may access and that its wall was verified. Your users get software they can open safely, and you get proof of what it can do.

The safety contract is simple and machine-readable. A Krate app may use only krate:* interfaces, so it can never reach the raw operating system, and every capability it wants is declared up front. That is a wall your agent can build against and your users can trust.
Why this is safe to share

An app can only touch what you allow

Running someone's app usually means trusting it with your whole computer. Krate turns that around. Every app declares what it needs, that list is shown to you before it runs, and it can never reach past what you approve.

Because the app was checked and its wall proven at the moment it was made, a broken or overreaching app never becomes a file you could send in the first place.

read/write ./checklistallowed
show a windowallowed
the rest of your filesblocked
the internetblocked
