# Authoring evidence

Evidence that an app can be authored and packaged into a permission-gated
`.krate` — by the built-in generator, by an external command, and by a real
coding model.

## Files

- `transcript.json` — the word-frequency CLI app authored by the built-in
  generator (`krate.author.v1`).
- `checklist-transcript.json` — the checklist GUI app authored through the
  `--author-cmd` seam. The `author` step records the external command that
  wrote the source; every downstream step (build, import check, pack, verify)
  is unchanged, and the verdict shows it runs with its grants and refuses
  without `fs.write`.
- `report.csv` — the word-frequency app's deterministic output.

The packaged `.krate` files are regenerated by the loop and are gitignored.

## Driving a real coding model

`krate create --author-cmd "<command>"` runs `<command>` to write the app,
handing it `KRATE_APP_DIR`, `KRATE_APP_NAME`, and `KRATE_REQUEST`. Two commands
are provided:

- `scripts/agent/claude-author.sh` — drives the `claude` CLI headlessly
  (`claude -p`) to write the three files, told the one hard constraint (a Krate
  component may import only `krate:*`) and pointed at the in-repo samples.
- `scripts/agent/standin-author.sh` — a deterministic stand-in that writes the
  files by hand, for proving the seam when a live model is not available.

Run it with a real model:

```sh
export KRATE_SDK_ROOT=/path/to/krate     # the agent references the samples
krate create "Make a checklist app that saves items to a local file" \
  --author-cmd "$KRATE_SDK_ROOT/scripts/agent/claude-author.sh" \
  --name checklist \
  --output checklist.krate
```

`krate create` then builds, import-checks, packs, and verifies whatever the
model produced. If the model writes an app that reaches outside Krate's
capabilities (a `wasi:*` import), the import check stops it before packaging —
so the guardrail holds regardless of what the model writes.

**Environment note (this repo's CI/dev box):** the `claude` CLI is installed but
its OAuth token was expired here, so the live-model run returned a 401 and could
not be captured in this environment. The `--author-cmd` seam itself is proven
end to end with `standin-author.sh` (see `checklist-transcript.json`, whose
`author` step is an external command, not the built-in generator). Re-run the
`claude-author.sh` command above on a box with a signed-in `claude` CLI to
capture a genuine model transcript.
